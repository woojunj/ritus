# 오프라인 지원

## Decisions

- `public/sw.js`로 화면을 보관한다. 앱 데이터는 기존 브라우저 저장소에 두고 서비스 워커에 별도 데이터 동기화 책임을 주지 않는다.
- 설치할 때 다섯 화면과 타이머 별칭 `/timer`, 각 HTML이 가리키는 `/_next/static` 파일을 미리 받는다. 아직 방문하지 않은 화면도 오프라인에서 열 수 있어야 한다.
- 화면 요청은 네트워크를 먼저 쓰고 연결 실패 때 보관본을 쓴다. 내용 해시가 있는 정적 파일은 보관본을 먼저 쓴다.
- 서비스 워커는 배포된 앱에서만 등록하고 개발 서버에서는 등록하지 않는다.

## Why

- 데이터가 이미 기기에 있어 화면을 그리는 파일만 보관하면 된다. 별도 도구 대신 작은 서비스 워커 하나로 범위를 한정한다.
- 화면을 네트워크 우선으로 받아 온라인 사용자는 새 배포를 받고, 정적 파일은 해시 이름을 활용해 재사용한다.

## Boundaries

- 오프라인 표시, 새 버전 알림과 같은 캐시 안의 오래된 배포 정적 파일 정리는 추가하지 않았다.
- 외부 도우미는 오프라인 지원 대상이 아니다. 프로덕션 빌드 검증은 `bun run test:offline`이 맡는다.
