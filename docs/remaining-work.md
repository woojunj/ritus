# 남은 일

현재 미확인 항목과 보류한 선택만 둔다. 끝낸 일의 이력은 Git에서 찾고, 증거가 있는 결함은 `docs/follow-ups/`에 둔다.

## 실기기에서 더 확인할 것

- [ ] **iCloud Drive의 전체 백업 복원**: 아이패드에서 전체 저장한 파일이 파일 앱 다운로드 폴더에 생기고 같은 기기에서 불러와지는 것은 확인했다. iCloud Drive로 옮긴 뒤 불러오는 것은 아직 확인하지 않았다.
- [ ] **양심노트 붙여넣기 오조작**: 한 장 화면의 복사 옆 붙여넣기를 잘못 누르는 일이 잦은지 써 본다. 잦으면 되돌리기를 검토하고, 아니면 넣지 않는다. 목록·한 장 붙여넣기 자체와 클립보드 권한 거절 시 직접 붙여넣기는 확인했다.
- [ ] **아이패드 외장 키보드**: 외장 키보드는 안드로이드 태블릿에서 사용자가 확인했다. 아이패드에서는 아직 확인하지 않았다. 확인할 때 Space 시작·일시정지·재개·재시작, 할 일 방향키 선택과 Space 이동, Tab·Shift+Tab 이동과 포커스 표시를 본다. 안드로이드 확인을 아이패드 확인으로 간주하지 않는다.
- [ ] **폰의 가상 키보드**: 메모장과 양심노트에서 키보드가 올라왔을 때 입력 중인 칸과 주요 조작이 가려지는지 확인한다. 기존 스펙에서 미확인으로 남긴 항목이다.

## 재발하면 기록할 것

- **윈도우 메모장 자모 분리**: 빠르게 한글을 칠 때 자모가 떨어져 보인 적이 있지만 헤드리스 크롬과 조합 명령으로 재현하지 못했다. 재발하면 메모장을 처음 열었을 때인지, 빠르게 칠 때인지, 저장 표시가 바뀔 때인지 기록한다.

## 보류

- **아이패드 소리**: 다른 앱이나 홈 화면에 있는 동안 소리가 끊기고, 돌아와 화면을 눌러야 다시 난다. 터치 뒤에도 늦을 수 있다. 현재 한계는 매뉴얼에 적었다.
  - 백그라운드에서 JS 타이머와 오디오 컨텍스트가 함께 멈춘다. 미리 예약하거나 `navigator.audioSession.type = "playback"`, `<audio>`를 쓰는 방법은 무음 모드에서도 소리가 나거나 다른 앱 음악을 멈출 수 있다. 무음 모드에서는 소리가 나지 않는 현재 동작을 유지하기로 한 결정과 부딪힌다.
  - 다시 검토할 때 현재 방식, 미리 예약, 예약과 재생 모드, `<audio>` 방식별 실험 화면을 미리보기로 배포한다. 각각 30초 동안 10초마다 소리를 내며 홈 화면·다른 앱, 무음 모드, 다른 음악 재생 중을 비교한다. 결과로 방식을 정한 뒤 실험 화면은 지운다.
- **옛 지정 브랜치 `claude/data-storage-sync-ppm62x`**: 원격에는 이 브랜치와 `main`만 남아 있다. 이 브랜치의 끝은 `d58800d`이고 `main`에 그대로 포함되지 않은 일반 커밋 3개와 병합 커밋 1개가 있다. 화면 꺼짐 방지와 복귀 후 소리 수정은 `main`에도 있지만 `chime.ts` 구현은 같지 않다. 예전의 "내용이 main에 모두 들어 있다"는 단정은 하지 않는다. 삭제나 강제 갱신 없이 보존한다.
