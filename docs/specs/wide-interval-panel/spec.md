# 와이드 화면에서 번갈아 반복 설정을 오른쪽 패널로

## 사용자에게 보이는 결과

설정 화면에서 번갈아 반복을 켰을 때, 가로가 충분히 넓은 화면에서는 반복 설정(두 구간 다이얼과 요약 문구)이 화면 아래로 펼쳐지는 대신 화면 오른쪽에 패널로 나타난다. 세로 스크롤 없이 설정 화면 전체가 한눈에 들어온다. 화면이 좁으면 지금처럼 아래로 펼쳐지는 방식을 그대로 쓴다.

## 승인된 범위

- 설정 화면(`SetupScreen`)에서 번갈아 반복을 켰을 때의 배치만 다룬다. 실행 화면·종료 화면은 대상이 아니다.
- 좁은 화면: 지금처럼 제목 → 시간 다이얼 → 번갈아 반복 토글 → (켜면) 반복 설정 → 시작 버튼이 한 세로 흐름으로 이어진다. 변경 없음.
- 넓은 화면: 제목 → 시간 다이얼 → 번갈아 반복 토글 → 시작 버튼으로 이어지는 중앙 세로 흐름은 그대로 두고, 번갈아 반복을 켜면 그 설정이 화면 오른쪽 여백에 별도 패널로 나타난다.
- 패널이 나타나고 사라지는 것은 토글 상태를 그대로 따른다. 토글 자체의 켜짐/꺼짐 동작은 바뀌지 않는다.

## 수용 기준

- [x] 가로 폭이 충분히 넓은 화면에서 번갈아 반복을 켜면, 반복 설정(두 다이얼과 요약 문구)이 화면 아래가 아니라 오른쪽에 나타난다.
- [x] 넓은 화면에서 반복 설정이 나타나도 세로 스크롤이 새로 생기지 않는다.
- [x] 좁은 화면(폰 폭 수준)에서는 번갈아 반복을 켰을 때 지금과 동일하게 화면 아래로 펼쳐진다.
- [x] 넓은 화면과 좁은 화면 모두에서 번갈아 반복을 껐다 켰다 하면 패널이 나타나고 사라지는 것 외에 값(구간 길이 등)은 유지된다.
- [x] 넓은 화면에서 중앙 흐름(제목, 시간 다이얼, 토글, 시작 버튼)의 위치는 반복 설정을 켜기 전과 비교해 좌우로 크게 밀리지 않는다.

## 확정된 제약과 근거

- 배치 전환 기준은 화면 가로 폭이다. 사용자가 실제로 겪는 불편이 "세로 스크롤"이지만, 스크롤 발생 여부 자체를 감지해 배치를 바꾸는 것은 신뢰하기 어려워 폭 기준 반응형 분기(지금 프로젝트가 이미 쓰는 방식, 예: `running-screen.tsx`의 `sm:` 분기)를 따른다. 정확한 임계값은 구현 시점에 정한다.
- 넓은 화면에서도 중앙 흐름은 지금 화면 그대로 두고 반복 설정만 오른쪽에 추가하는 방식(사이드 패널)을 택했다. 전체를 두 칸으로 재구성하는 대안도 검토했으나, 반복을 껐을 때와 켰을 때 화면 구조 차이가 커지는 것보다 변경 범위가 작은 쪽을 우선했다.
- `PRODUCT.md`의 "화면이 커지면 그 화면도 함께 커진다"는 네이티브 앱 설치 없이 브라우저 반응형으로 대응한다는 뜻으로 읽었다. 이 프로젝트가 이미 폭 기준 반응형 분기를 쓰고 있어(`icon-minimal-ui` 스펙의 `sm:text-2xl` 등), 폭에 따라 반복 설정 배치를 바꾸는 것이 이 원칙과 부딪히지 않는다고 판단했다.

## 가정

- 배치가 바뀌는 정확한 폭 임계값, 오른쪽 패널의 폭·간격·나타나는 방식(즉시 전환 vs 애니메이션)은 구현 시점에 정한다. 세로 스크롤이 생기지 않는 것과 중앙 흐름이 크게 밀리지 않는 것만 이번 기준으로 둔다.
- 패널이 중앙 흐름과 시각적으로 한 화면임을 알 수 있게 묶이는 것으로 충분하고, 카드 형태·구분선 등 구체적 시각 처리는 구현 시점에 정한다.

## 범위 밖

- 실행 화면·종료 화면의 레이아웃: 이번 불편은 설정 화면에서만 보고됐다.
- 배치 전환 기준을 폭이 아닌 실제 종횡비(가로/세로 비율)나 스크롤 발생 감지로 정교화하는 것: 폭 기준으로 충분하다고 보고 더 다루지 않는다.
- 모바일에서 화면을 가로로 돌렸을 때의 별도 처리: 폭 기준 분기에 자연히 포함되므로 따로 다루지 않는다.
